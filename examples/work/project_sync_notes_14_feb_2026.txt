DISCUSSION
----------
1. Parsing: TXT extraction is straightforward. DOCX paragraph order must be retained, and tables need to be flattened into readable rows. PPTX needs slide titles, body text and speaker notes only if available. Log skipped files rather than silently producing empty documents.
2. Retrieval: create one chunk per short document and split longer material at section boundaries. Preserve path, extension, modification date and original filename as metadata. Use a lexical baseline before tuning vector similarity. Exact identifiers such as invoice numbers should still be searchable.
3. Ranking: blend semantic similarity with optional filename match and date filters. Numeric-heavy exports may appear semantically close because they contain many category tokens, so test down-ranking tables when natural-language queries are clearly unrelated. Do not universally discard tables; a query for a bill amount should still retrieve a billing table.
4. Privacy: keep the sample corpus synthetic. For a local demo, explain where embeddings are stored and whether any content leaves the machine. Do not index browser profiles, authentication tokens, or private chat exports.
